# Runbook (owner)

Operational procedures that need access to the Cloudflare account, the
Telegram bot, or the GitHub repository settings. Moved out of the README on
2026-08-05 when the repository went public: none of this is actionable without
owner credentials, and it was the only place the production Worker URL was
written down in the clear.

Throughout, `<your-worker>.workers.dev` stands for the deployed Worker origin.
Do not commit the real hostname.

## Public-repository warning: scheduled workflows expire

GitHub automatically disables scheduled workflows in a **public** repository
after 60 days with no repository activity. `.github/workflows/ingest-relay.yml`
runs on `*/30 13-21 * * 1-5` and feeds the treasury, CFTC, and House PTR lanes.
If the repository goes quiet for two months, those lanes stop and nothing
raises an alarm.

Mitigation: any commit resets the clock. Re-enable from the Actions tab, or:

```bash
gh workflow enable ingest-relay.yml
```

This risk did not exist while the repository was private.

## Deploy (one-time setup)

1. `wrangler d1 create skeptic-wire`, then paste `database_id` into
   `wrangler.toml`.
2. `wrangler kv namespace create KV`, then paste `id` into `wrangler.toml`.
3. `wrangler d1 migrations apply skeptic-wire --remote`.
4. `npm run deploy`.

Secrets are set with `wrangler secret put <NAME>` only, never committed.

## Telegram approval queue setup

1. **Create the bot.** In Telegram open **@BotFather**, send `/newbot`, pick a
   display name and a unique username ending in `bot`. Copy the token.
2. **DM the bot** (open its profile, press Start, send any message).
3. **Find the chat id.** This must happen BEFORE the webhook is set, because
   `getUpdates` and webhooks are mutually exclusive:
   ```bash
   curl -s "https://api.telegram.org/bot<TOKEN>/getUpdates" | python3 -m json.tool | grep -A2 '"chat"'
   ```
   The numeric id is `result[].message.chat.id`.
4. **Set the secrets** (after the Worker is deployed):
   ```bash
   wrangler secret put TELEGRAM_BOT_TOKEN
   ```
   ```bash
   wrangler secret put TELEGRAM_WEBHOOK_SECRET   # e.g. openssl rand -hex 32
   ```
   Put `TELEGRAM_CHAT_ID = "<your id>"` under `[vars]` in `wrangler.toml`, then
   redeploy.
5. **Point the webhook at the Worker:**
   ```bash
   curl -s "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d url="https://<your-worker>.workers.dev/tg/webhook" \
     -d secret_token="<same secret as TELEGRAM_WEBHOOK_SECRET>" \
     -d allowed_updates='["message","callback_query"]'
   ```
6. **Verify.** Send `/start` to the bot and it replies with the chat id.
   `getWebhookInfo` shows delivery errors if anything is off.
7. **Smoke test the full loop** (message, buttons, decision round-trip):
   ```bash
   curl -s -X POST "https://<your-worker>.workers.dev/admin/seed-test" \
     -H "X-Admin-Key: <same value as TELEGRAM_WEBHOOK_SECRET>"
   ```
   A fake draft appears in the chat. Approve, Edit, and Reject all work, and
   the decisions round-trip through D1.

## Ingest relay (courier) setup

1. Generate a secret and set it on the Worker:

   ```bash
   openssl rand -hex 32
   ```

   ```bash
   npx wrangler secret put INGEST_SECRET
   ```

2. Add the same value as a GitHub repository secret named `INGEST_SECRET`,
   plus `WORKER_URL` set to the Worker origin
   (Settings, then Secrets and variables, then Actions).

Until step 1 is done the endpoint returns 503 and ingests nothing, so deploying
ahead of the secret is safe.

**Rotate `INGEST_SECRET` after any change to repository visibility.** The
source now publicly documents the endpoint path and the header name, so the
secret itself is the entire control.

## Kill switch

Note `--remote`. Without it wrangler v4 writes to LOCAL simulated storage and
production keeps running.

```bash
wrangler kv key put kill_switch 1 --binding KV --remote
```

Resume:

```bash
wrangler kv key delete kill_switch --binding KV --remote
```

## Threads un-park (only if the appeal succeeds)

The Threads account (@skeptictradess) was banned by Meta on suspected bot
activity on 2026-07-28. Publishing is manual on X. The client is kept on disk
for the appeal. Full incident record, including how a ban was distinguished
from an expired token:
[verification/2026-07-28-threads-ban.md](verification/2026-07-28-threads-ban.md).

Deliberately three steps, because a banned account cannot be probed back to
life:

1. Flip `THREADS_PARKED` to `false` in [../src/poster.ts](../src/poster.ts),
   restore the two OAuth routes in [../src/index.ts](../src/index.ts), and
   restore the `poster` and `threads_token_refresh` entries in
   [../src/jobs.ts](../src/jobs.ts).
2. Re-enable the jobs rows:
   ```bash
   wrangler d1 execute skeptic-wire --remote --command "UPDATE jobs SET enabled = 1 WHERE name IN ('poster','threads_token_refresh')"
   ```
3. Re-run the OAuth flow in a browser. Not optional: the long-lived token
   expires 2026-09-25 and a dead token cannot be refreshed.

Then set `POSTING_ENABLED = "true"` in `wrangler.toml` via PR.
