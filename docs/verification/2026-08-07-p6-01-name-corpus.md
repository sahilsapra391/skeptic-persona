# p6-01 (A1) — display names: the corpus, the rules, and what live data changed

Date: 2026-08-07. Chunk: p6-01. Program: P6 (display law, insider focus).
Cited by `src/lib/names.ts`.

## What was fetched, and how

Declared User-Agent `Skeptic Wire admin@spechawk.ai`, sequential, ~7 req/s,
well under SEC's 10 req/s ceiling.

- **60 live Form 4 ownership documents**, pulled from
  `browse-edgar?action=getcurrent&type=4&output=atom` and their filing
  directories on 2026-08-07 between 17:11 and 17:14 ET. 49 distinct
  reporting-owner names.
- **115 distinct filer names** read out of production D1 (`items.payload`,
  `$.owners[0].name` for `edgar_form4` and `$.sellerName` for `sec_form144`),
  most recent 120 insider items.

The second corpus is the one that matters. It is what the pipeline has
actually stored, and it broke rules that the first corpus had passed.

## The rules, and why each exists

**Classification.** Digits, a bracket, `&`, `/`, or any token from the entity
list makes a name an ENTITY, and an entity is never reordered. Person shape is
2 to 4 tokens. Anything else renders as filed.

**Casing, two rules, no surname dictionary.**

1. A filing written entirely in caps carries no case information, so every
   token is rebuilt: `FALTISCHEK DENISE M` becomes `Denise M. Faltischek`.
2. A filing that already mixes case chose its casing, so tokens are left
   byte-for-byte alone. This is what keeps `McNulty`, `DeLuca`, `O'Brien`,
   `Lee-Lean`, `GIC`, `TAFE` and `SCSp` correct without a dictionary.
   Lowercasing and re-capitalizing them would have produced `Mcnulty` and
   `Deluca`, destroying information the filing carried.

**Ordering.** EDGAR's documented convention is `LAST FIRST MIDDLE`, and the
default is to flip. Two signals withhold the flip, and neither can ever create
one:

- a **periodled middle initial** (`Nigel W. Morris`, `KEVIN J. KRAUS`,
  `Paul B. Murphy Jr.`) means the name is already natural, because in EDGAR
  order the initial is a middle name and lands last;
- a **leading given name with a non-given last token** (`KATHERINE ANN MAHER`,
  `Mat Ishbia`, `David Zeiden`, `Cheryl de Mesa Graziano`).

## What the live corpus disproved

The synthetic corpus passed 78 tests. Then the same code ran over the 115 real
production names and produced five defects it could not have found otherwise.

| # | Filed | Wrong output | Cause |
|---|---|---|---|
| 1 | `YUCCA (JERSEY) SLP` | `(jersey) Slp Yucca` | brackets were not an entity marker and `SLP` was not a legal-form token |
| 2 | `INDEX VENTURES GROWTH III (JERSEY), L.P.` | `... (jersey), L.P.` | `capitalize()` upper-cased index 0, which was the bracket, so the word lower-cased |
| 3 | `Nigel W. Morris` | `W. Morris Nigel` | the name was already in natural order |
| 4 | `KATHERINE ANN MAHER` | `Ann Maher Katherine` | natural order with no punctuation to give it away |
| 5 | `Mat Ishbia`, `David Zeiden`, `DAVID CLEMENT` | `Ishbia Mat`, ... | two-token natural order |

**The premise that failed is the one the whole module rested on: EDGAR is not
uniformly `LAST FIRST`.** A minority of filer agents ignore the field
convention. Nothing in the plan, the schema docs, or the 60-filing sample said
so; only production did.

Defect 3 was also caught independently by `test/form4.test.ts`, whose fixtures
used `name: "Jane Doe"` — natural order, a shape the parser never receives.
Those fixtures were rewritten to `"Doe Jane"` so the test exercises real input.

## Result after the fixes

Over all 115 live production names:

```
person    100
as-filed    9
entity      6
changed   107 of 115
derivability failures: NONE
```

Every one of the nine suppressions was manually checked and every one is a
genuine natural-order name. Zero over-fires.

## The licensing property

`entityCheck` (`src/rag/validate.ts:1045`) licenses any name appearing in the
payload JSON, and `display_name` now lives in that JSON. **The validator
therefore cannot be what proves the derivation honest — its haystack is the
string being added.**

`displayIsDerivable()` is the independent proof, asserted over the whole live
corpus: every alphanumeric run in the display must trace to one in the filed
string. Reordering, case-folding, lowering a particle, adding a period and
dropping a boilerplate tail all preserve it. Inventing a token does not, and
the test asserts the negative cases too (`Carl A. Merton` passes,
`Carl Anthony Merton` fails, `GIC Private Limited` fails).

## The one way to misuse this module

`deriveDisplayName("Jane Doe")` returns `"Doe Jane"`, and it is right to: its
premise is that the input is filed `LAST FIRST`, and no heuristic separates the
two. It belongs only at call sites whose source convention is known. Today
there are exactly two, both live-verified 2026-08-07:

- `rptOwnerName` (Form 4 ownership XML)
- `nameOfPersonForWhoseAccountTheSecuritiesAreToBeSold` (Form 144)

`test/names.test.ts` pins this hazard rather than hiding it.

## Residual, stated not rounded

A two-token name where the leading token is not in the given-name list and the
name is nonetheless natural will still flip. None remain in the 115-name
corpus, but the list is a heuristic and not an authority. The failure mode is
bounded by construction: the list can only withhold a flip, so a miss leaves a
name in EDGAR order (ugly) rather than reassigned (invented).
