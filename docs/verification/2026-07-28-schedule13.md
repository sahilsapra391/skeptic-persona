## THE NAMING TRAP (re-confirmed live)

| Query | Entries returned |

| `type=SCHEDULE+13D` | **40** |
| `type=SC+13D` | **1** |

The EDGAR form type is literally `SCHEDULE 13D`, not `SC 13D`. A poller built
on the obvious spelling returns HTTP 200 with valid Atom and no error, while
missing roughly 99% of filings. This is the same silent-filter class as the
Federal Register's `PRESDOCU` and CFTC's contract names.

Same duplicate-per-accession quirk as Form 4 and Form 144: each filing

issuer (`(Subject)`), sharing an accession. Dedup or every stake posts twice.

The feed carries **no numbers at all** — form type, names, CIKs, accession
and date only. Every figure requires the document fetch.

## Doctrine

- **Numbers come from the COVER PAGE only.** The narrative Items are
  unreliable in practice — the roadmap pass found `item4` reading "See Item 3
  above" and `item5` reading "Not applicable" — and are never read for a
  figure.
- `percentOfClass` is a plain decimal string with no `%`, and share powers
  carry `.00` decimals. Cast, never string-match.
- A 13D signals **activist intent**; a 13G is passive. The grading reflects
  that: a 6% 13D is postable while a 6% 13G is lake-only.
- **Amendments carry no beat.** They restate a position we may already have
  posted.
